# Agentic Vision

画像を「一度見て答える」と、細部の質問ではよく間違える。全体像は縮小されて届くし、一瞥では数え漏れや読み違いが起きる。このスキルは、Gemini の Agentic Vision と同じく **Think → Act → Observe** のループで、根拠を自分の目で確かめてから答えるための手順とツールを提供する。

## なぜ必要か

- 画像は長辺 約1568px / 約1.15MP を超えると縮小されてから見える。4000x3000 の写真なら約 1/3.5 に縮小され、元画像で 15px の文字は 4px 程度になり読めない。読めない文字を「それらしく」補完してしまうのが最大の失敗パターン。
- 切り出して拡大すれば、元画像の画素がそのまま届く。情報量が実際に増えるのはこの操作だけ。
- 数え上げは一瞥だと ±10〜20% ずれやすい。領域を分けて数え、印を付けて検算すると安定する。

## 使わなくてよいとき

「何の写真？」「雰囲気は？」のように全体像だけで答えが決まる質問。画像がなくテキストだけの質問。ループは数ステップかかるので、細部が答えを左右するときだけ回す。

## 準備

画像はファイルとして手元にある必要がある (アップロードは通常 `/mnt/user-data/uploads/`)。見つからないときは Glob で探す。会話に貼られた画像しかなくファイルがない場合は、ファイルとして添付し直してもらうよう一言頼み、それまでは通常の観察で暫定回答する (暫定であることを明記)。

スクリプト: `scripts/vision.py` (Pillow が必要。なければ `pip install pillow`)。以下 `V` はこのスクリプトのパス。

```bash
python V init /path/to/image.jpg      # 作業フォルダ ./vision_ws を作成、EXIF の向きも補正 (PNG/WebP/GIF/BMP/TIFF も可。透過は白背景に合成。HEIC は pillow-heif が必要。PDF/SVG は非対応)
```

`init` は元画像のサイズと「全体表示で何分の1に縮小されるか」を表示する。この縮小率が、全体表示を信用してよい細かさの目安になる。

## ループ

### 1. Think — 何を確かめるかを書き出す

overview.png (または会話中の画像) を見て、答えに必要な細部を列挙する。例:「右下のラベルの文字列」「赤い丸の総数」「針がどの目盛りの間にあるか」。あわせて、全体表示で見えたこと・見えなかったことを分けて書く。ここで答えを決め打ちしない。

### 2. Act — 画像を加工する

| 目的 | コマンド |
|---|---|
| どこを切るか座標を知りたい | `python V grid --rows 8 --cols 8` (範囲を絞るなら `--box l,t,r,b`) |
| 細部を読む | `python V crop l t r b` (`--pad 0.1` で少し余白) |
| 小さい範囲をぼやけを抑えて拡大 | `python V upscale --box l,t,r,b` (既定は簡易方式。それでも解釈が難しいときだけ `--method edsr`) |
| 密集・広範囲を漏れなく見る | `python V tile --rows 3 --cols 3` (`--box` で範囲限定) |
| 傾き・上下逆・暗い・かすれ | `python V adjust --box l,t,r,b --rotate 180 --autocontrast --sharpen` |
| 数えた結果・位置の検算 | `python V annotate --points "x,y;x,y;..."` (`--view` で範囲表示) |

座標は **すべて元画像に対する 0.0〜1.0 の割合** (左上が 0,0)。crop や tile の出力にグリッドを重ねてもラベルは元画像座標で出るので、見えた値をそのまま次の crop に渡せばよい。crop は常に元画像の画素から切り出すので、切り出しを重ねても画質は落ちない。

**upscale の使い分け**: crop は元画像の画素をそのまま拡大するだけなので、数十px 角の小さい対象は輪郭がにじむ。そういうときは `upscale` を使う。既定の簡易方式 (弱いぼかし → 段階的な Lanczos 拡大 → 弱いシャープ) で足りないときに限り `--method edsr` (AI 超解像 4倍) を補助に使う。EDSR は `opencv-contrib-python` が必要で、初回に重み (約38MB) を `~/.cache/agentic-vision/` へ取得する。範囲は約 316x316px 以下に絞ること。どちらも元画像にない情報は作れず、EDSR は推定で描き足すので、**位置や形の確認にだけ使い、文字や数値を読む根拠にしない** (読めないものは「判読不能」のまま)。

見ている画像の上で位置を指したいときは、割合に換算せず `--px-of 画像名` を付けてその画像の画素座標で渡せる (crop と annotate)。例: `python V annotate --px-of tile_4.png --points "385,229;593,246"`。暗算での換算ミスがなくなるので、数え上げの検算ではこちらを使う。

例外は adjust の出力だけ (回転などで元画像と対応しなくなる)。adjust の出力からさらに切るときは `--source adjust_N.png` を付け、座標はその画像自身の割合で指定する。

### 3. Observe — 出力を見て、読み取ったことを書き留める

各コマンドは保存先を表示するので、その PNG を Read で開いて見る。見たら、読み取った内容 (文字列、数、位置、確信度) をすぐテキストで書き留める。後で何枚も見比べると記憶が混ざるため。

出力に表示される「元画像1px → Npx」を確認する。N < 1 ならまだ縮小されているので、もっと狭く切る。N > 1 の拡大は見やすくなるだけで、元画像にない情報は出てこない。そこまで拡大しても読めない文字は「判読不能」と扱う。

確かめたいことが残っていれば 1 に戻る。目安は 3〜8 回。同じ範囲を同じ加工で何度も見直すのは進展がないサインなので、加工方法を変えるか、読めた範囲で結論を出す。

## タスク別の進め方

**小さい文字・型番・ラベル**: grid で位置を特定 → 文字の行が画面幅の半分以上を占めるくらいまで crop → 読めない文字があれば adjust (`--autocontrast --sharpen`、かすれなら `--threshold 128` 前後、白抜き文字なら `--invert`)。0/O、1/l/I、5/S、8/B は特に疑い、別の加工でも読んで一致を確かめる。

**数え上げ**: まず対象の定義を決める (どの色・形を含めるか、見切れているものは数えるか)。1タイルあたり 5〜15 個程度になるよう tile で分割する。各タイルには水色の枠 (担当範囲) が描かれるので、**中心が枠の内側にある対象だけ** を数え、タイルごとに数と画素座標を書き出す。枠の外側の重なり部分は境界上の対象を見切れずに判断するための余白で、数えない。こうすれば重なりによる二重カウントは起きない。検算は `annotate --px-of tile_N.png --points ...` でタイルごとに印を描き、印のない対象・二重の印・紛らわしい色の取り違えがないか見る。合計はタイルごとの数の和。

**メーター・グラフ・図面の値読み**: 目盛りの数字と針・点の位置の両方が読める範囲を crop。目盛り間の位置は grid の細かい線で内挿する。軸ラベルや単位も必ず確かめる (対数軸、単位の桁)。

**表・密なスクリーンショット**: 行ごとや列ごとに帯状に crop して読む。行がずれていないか、隣の行の値と取り違えていないかを見出しと照合する。

**向き・画質の問題**: 文字が逆さ・横向きなら adjust `--rotate` (時計回りが正)。わずかな傾きはそのままでも読めることが多い。暗い写真は `--equalize` か `--brightness 1.8`、霞んだ写真は `--autocontrast`。

**位置関係・比較**: 比べる2箇所を同じ倍率で crop するか、両方を含む範囲に annotate で枠を付けて見る。

**内部整合性で検算する**: 画像の中に答えを裏付ける関係があれば必ず使う。レシートや表なら明細の和と小計・合計、日付と曜日、グラフなら凡例と線の色、図面なら寸法の和と全長。合わなければどこかを読み違えているので、その数字をもう一度別の加工で読む。

## 回答のしかた

- 結論を先に。そのあと根拠を簡潔に (どの範囲をどう加工して何が見えたか)。
- 読めなかった部分は推測で埋めず、「3文字目は 8 か B か判別できない」のように不確かな箇所を明示する。数え上げで判断に迷う対象 (半分隠れている等) があれば、その扱いと数を添える。
- 加工画像はユーザーに見せる必要はないが、根拠として役立つ1枚 (annotate の結果など) は提示してよい。
