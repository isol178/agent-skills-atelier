# PR の図解の作り方

SKILL.md の Phase 4 で、図解を作ることにユーザーが同意した後に読む。

## 出力先を決める

使える手段のうち、上から順に選ぶ。

1. **ハーネスが提供する図解・ページ公開の機能**（例: Claude Code の Artifact ツール）。その機能に専用の手順やガイド（skill など）があれば、先に読んでから作る
2. **単一の HTML ファイル**: スクラッチパッドか一時ディレクトリに置き、パスをユーザーに伝える。外部のスクリプトに頼らず、インライン SVG で描く
3. **Mermaid**: 応答に直接書く。表示できる環境かどうか分からない場合は、その旨を添える

ページを公開する機能を使った場合は、誰が閲覧できるか（既定で非公開か、PR の作者などと共有するには何が必要か）をユーザーに伝える。

## 図の選び方

図にはそれぞれ 1 つの主張を持たせ、仕組みそのものを描く。箱に名前を並べるだけの図にしない。PR に応じて次から選ぶ。

| 図 | 向いている PR | 描き方 |
|----|--------------|--------|
| 利用者から見た流れ | 新しい操作手順・API | シーケンス図。初回、継続、例外経路（使えない経路も含む）をフェーズ帯で分ける |
| 実装の構成 | 新しいモジュール群・経路 | リクエストの経路と、設定・派生値の関係。矢印にはラベルを付ける（例: 「照合」「起動時に構築」） |
| 判定ロジック | 分岐や判定関数が中心 | フローチャートと、入力ごとの結果の表 |
| なぜこの設計か | 設計方針の変更 | 採らなかった構成と採った構成を並べ、違いが出る辺を描く |
| 失敗に気付くタイミング | 設定・起動処理の変更 | 起動時 / 初回実行時 / 気付けない、の表 |

## 内容のルール

- 判定関数が中心の PR では、同じ順序で判定を再現する小さなシミュレーターを付けると理解が速い（HTML で出す場合）。最初から例の入力を実行済みにしておく
- 例の値（モデル名、ID など）は例と明記する。PR の記述をもとに推定した部分は、そう書く
- 図の基準は PR SHA 時点のコードとし、ページに PR 番号と PR SHA を載せる
- Phase 3 で投稿した指摘があれば、ページの最後に thread ID と図のどこに当たるかの対応を載せる
- 描画を自分で確認していなければ、そう伝える
